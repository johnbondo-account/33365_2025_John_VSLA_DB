# Phase V – Table Implementation

## 1. Overview

The VSLA Management System database was implemented using Oracle SQL Data Definition Language (DDL). The implementation consists of twelve (12) relational tables that store business data for member registration, savings groups, financial transactions, meetings, user accounts, and auditing.

Each table was created with appropriate data types, primary keys, foreign keys, unique constraints, check constraints, and default values to ensure data integrity and support the business requirements of the system.

---

## 2. Table Summary

The following tables were created during the implementation of the database:

| Table | Description |
|--------|-------------|
| SAVINGS_GROUPS | Stores information about savings groups. |
| MEMBERS | Stores member information. |
| APP_USERS | Stores application user accounts. |
| CONTRIBUTIONS | Records savings contributions. |
| LOAN_APPLICATIONS | Stores loan applications. |
| LOANS | Stores approved loans. |
| LOAN_REPAYMENTS | Records loan repayments. |
| PENALTIES | Stores penalties issued to members. |
| MEETINGS | Stores scheduled meetings. |
| SHARE_OUTS | Stores share-out transactions. |
| PUBLIC_HOLIDAYS | Stores public holiday information. |
| AUDIT_LOG | Stores audit records generated by the system. |

---

## 3. Constraints Used

The following Oracle constraints were implemented throughout the database:

- Primary Key (PK)
- Foreign Key (FK)
- NOT NULL
- UNIQUE
- CHECK
- DEFAULT

These constraints ensure valid data entry, maintain referential integrity, and enforce business rules within the database.
